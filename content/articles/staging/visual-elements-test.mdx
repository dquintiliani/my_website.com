This is an unlisted staging article — it exists to show what each supported markdown element actually looks like rendered on the site, so you can see the options before writing a real post.

## Text formatting

A paragraph can mix **bold text**, *italic text*, and `inline code` in the same sentence. It can also link out to an external site like [Anthropic](https://www.anthropic.com) or point to an internal page like [the blog index](/blog).

## Blockquote

> Pull a key sentence out as a blockquote when you want it to stand apart from the surrounding paragraph — it renders indented, italic, with a left rule.
> A blockquote can span multiple lines like this one does.

## Callout / note

Use for a supporting aside that shouldn't carry full paragraph weight. Source:

```md
:::note
A short supporting note — **bold** and other inline formatting still work.
:::
```

Rendered:

:::note
A short supporting note — **bold** and other inline formatting still work.
:::

## Key takeaway

Same block, `takeaway` instead of `note` — use for the one line you want a skimming reader to catch. Source:

```md
:::takeaway
The one thing to remember from this section.
:::
```

Rendered:

:::takeaway
The one thing to remember from this section.
:::

Any other `:::type` you invent (e.g. `:::warning`) still renders as a bordered box via a `callout-<type>` class — it just won't have custom colors until one is added in `app/styles/sections/blog.css`.

## Definition card

For glossary-style posts — a bordered term/definition pair, more scannable than a table row. The word after `:::term` is the term itself. Source:

```md
:::term Kubernetes
An open-source system for automating deployment, scaling, and management of containerized applications.
:::
```

Rendered:

:::term Kubernetes
An open-source system for automating deployment, scaling, and management of containerized applications.
:::

## Pull quote

For emphasis, not citation — large centered text, optionally with an attribution. Source:

```md
:::pullquote — Teresa Torres
What AI gives you is a well-reasoned starting point. What you do with it determines whether it's valuable.
:::
```

Rendered:

:::pullquote — Teresa Torres
What AI gives you is a well-reasoned starting point. What you do with it determines whether it's valuable.
:::

## Footnotes

For citation-heavy pieces, so a source doesn't interrupt the sentence. Reference a footnote inline with `[^id]`, then define it anywhere in the document with `[^id]: text` — numbering follows the order refs first appear, not the order definitions are written. Source:

```md
A claim worth citing.[^torres]

[^torres]: Torres, *Continuous Discovery Habits*, 2021.
```

Rendered: a claim worth citing.[^torres] Reusing the same `[^id]` again links to the same numbered entry — just don't reuse it more than once on the same page, since the jump target isn't unique per repeat.

## Lists

Unordered list:

- First point
- Second point with **bold** inside it
- Third point

Ordered list:

1. Do this first
2. Then this
3. Then this

## Code block

Fenced code blocks keep their formatting and get a monospace, dark background treatment — good for snippets:

```ts
function greet(name: string): string {
  return `Hello, ${name}!`
}
```
